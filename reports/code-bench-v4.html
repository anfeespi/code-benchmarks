Yuno code benchmark v4 — seven models, one baseline

AI Squad · Yuno
2026-09-02
Verdict. Seven models regenerated on the same day, same protocol, same rebuilt suite. Grok 4.5 and Gemini 3.8 Flash pass 48/48; Gemini is the cheapest run ($0.72) and twice as fast as Grok. Claude Fable 5.1 passes 40/48: it refuses 8 prompts (optimization and algorithms) and is 100% correct on everything it attempts. Kimi K3 (40) and GLM 5.2 (35) lose answers by exhausting the 16k output cap on reasoning; Opus 5 and Fable 5 (35 each) refuse 13 and are perfect on the rest. The Claude 5 raw-API refusal remains the operational risk, but it moved from 30/48 (Fable 5, July) to 8/48 (Fable 5.1).

What was tested

48 in-house HumanEval-style Python problems in six categories (algorithms, data structures, optimization, bug fixing, spec compliance, edge cases; 8 each). Each model receives the problem prompt as the only user message, no system prompt (Claude: no temperature; OpenRouter models: temperature 0). Grading is by execution: the candidate module is imported in a sandboxed child process (memory and time limits) and run against the test cases; pass requires every case, tests_ratio is the fraction passed, checker is 1 when the module loads and defines the entry point. Refusals (stop_reason: refusal) and empty answers score 0 and are reported separately so they are never confused with wrong code.

The v4 suite. Both July runners were lost, so the suite was rebuilt from the problems and canonical solutions stored in Braintrust: 461 cases (6-15 per problem), expected values generated by executing the canonical solution, and a large deterministic input per optimization problem sized so a quadratic solution times out while the canonical runs in under a second. The suite was calibrated against the stored July 25 outputs of five models: 89.6% agreement on pass (215/240). Every disagreement was reviewed: 21 go in the model's favour (July tests stricter than the prompt; the outputs are behaviourally identical to the canonical under fuzzing) and 4 are real bugs July missed. Candidates run on Python 3.12 (the prompts never pin a version; on 3.9 two correct Gemini solutions failed on int | None and bisect(key=)). The suite, harness and every output now live in the code-benchmarks repository.

One baseline. All seven models were generated on September 2 with a 16,384-token output cap. Two kinds of empty answer are reported separately: the Anthropic API classifier refusing a benign prompt (stop_reason: refusal) and a reasoning model exhausting the output cap without emitting code (finish_reason: length; retrying at 32k changed nothing, the provider caps Kimi and GLM at 16,384). Two Opus 5 requests hit 529 Overloaded and were retried successfully.

Findings

  • Grok 4.5 and Gemini 3.8 Flash clear the whole suite. Both 48/48 with no empty answers. Gemini does it at $0.72 and 21.7 s per problem (3965 output tokens); Grok takes 45.8 s per problem, twice its July pace, with longer answers (2.6k tokens). Grok also fixes the two cases its July outputs got wrong (FIFO scheduler re-submission, str.format where forbidden).
  • Fable 5.1 attempts far more and never misses. 8 refusals (5 optimization, 3 algorithms; the other four categories are 8/8) and 40/40 on what it answers, with the shortest answers in the set (1263 tokens, 17.0 s). Fable 5 itself, regenerated today, refuses 13 instead of July's 30 on identical prompts: the classifier moved on Anthropic's side, and the model is 35/35 when it answers. Opus 5: 13 refusals, 35/35.
  • Reasoning models hit the output cap. Kimi K3 leaves 6 problems and GLM 5.2 leaves 12 with no code after 16,384 output tokens of reasoning; retrying with a 32k budget changed nothing because the provider caps both there. On what they deliver they are strong (Kimi 40/42, GLM 35/36), but Kimi is now the most expensive run ($4.09) and, with Grok, the slowest.
  • Two empties, one score. A refusal and an exhausted cap both score 0 like a wrong answer and are invisible unless stop_reason / finish_reason is inspected. Every Claude 5 refusal in this suite came from bare code prompts over the raw API; the Maia agent evals run on Fable without a single refusal.

Recommendation

For autonomous code agents on the raw API, Gemini 3.8 Flash and Grok 4.5 are the frictionless choices; Gemini wins on cost and latency. Fable 5.1 is viable where a supervising loop can detect a refusal and re-route (its accuracy is the best in the set), and refusal rates should be re-measured on every release: Fable 5 went from 30 to 13 refusals in five weeks with no version change. Give reasoning models (Kimi, GLM) a larger output budget where the provider allows it, or expect empty answers on the hardest prompts. Keep the suite in the repository and re-run calibrate before every comparison.
