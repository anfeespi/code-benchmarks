Yuno code benchmark v4 — seven models, execution-graded

AI Squad · Yuno
2026-09-02
Verdict. On the rebuilt 48-problem suite, Gemini 3.8 Flash passes 48/48 with no friction and the cheapest run ($0.72). Claude Fable 5.1 passes 40/48: it refuses 8 prompts (all optimization and algorithms) but is 100% correct on everything it attempts, closing most of the gap left by Fable 5 (16/48, 30 refusals). Kimi K3 (47), Grok 4.5 (45) and GLM 5.2 (44) keep their July order. The Claude 5 raw-API refusal pattern is still the operational risk for autonomous code agents, but it is now 8/48 instead of 30/48.

What was tested

48 in-house HumanEval-style Python problems in six categories (algorithms, data structures, optimization, bug fixing, spec compliance, edge cases; 8 each). Each model receives the problem prompt as the only user message, no system prompt (Claude: no temperature; OpenRouter models: temperature 0). Grading is by execution: the candidate module is imported in a sandboxed child process (memory and time limits) and run against the test cases; pass requires every case, tests_ratio is the fraction passed, checker is 1 when the module loads and defines the entry point. Refusals (stop_reason: refusal) and empty answers score 0 and are reported separately so they are never confused with wrong code.

The v4 suite. Both July runners were lost, so the suite was rebuilt from the problems and canonical solutions stored in Braintrust: 461 cases (6-15 per problem), expected values generated by executing the canonical solution, and a large deterministic input per optimization problem sized so a quadratic solution times out while the canonical runs in under a second. The suite was calibrated against the stored July 25 outputs of five models: 89.6% agreement on pass (215/240). Every disagreement was reviewed: 21 go in the model's favour (July tests stricter than the prompt; the outputs are behaviourally identical to the canonical under fuzzing) and 4 are real bugs July missed. Candidates run on Python 3.12 (the prompts never pin a version; on 3.9 two correct Gemini solutions failed on int | None and bisect(key=)). The suite, harness and every output now live in the code-benchmarks repository.

Findings

  • Fable 5.1 attempts far more and never misses. 8 refusals against Fable 5's 30 on identical prompts (5 optimization, 3 algorithms; bug fixing, spec, data structures and edge cases are 8/8), and 40/40 on what it answers, with the shortest answers of the fresh runs (1263 tokens, 17.0 s). The mechanism is unchanged — the API safety classifier declines benign code prompts with an empty body — but it fires four times less often.
  • Gemini 3.8 Flash is the first model to clear the whole suite. 48/48 at $0.72 for the run, 21.7 s per problem, verbose (3965 output tokens, second only to GLM). No refusals, no truncation.
  • Opus 5 remains the most accurate Claude when it answers (35/35 attempted, 100%) but still refuses 13/48; those are July 25 outputs, not re-generated here.
  • What v4 changed. Grok 4.5 loses two real cases the July suite did not exercise: it resets a re-submitted task's version in the FIFO scheduler (served at its old position) and uses str.format where the prompt forbids it; Grok and Fable 5 crash with TypeError in the colour-graph heap on cost ties. Kimi K3's only miss is competition ranking implemented as dense ranking.
  • Refusal is the operational risk, not capability. A refusal scores 0 like a wrong answer and is invisible unless stop_reason is inspected. Every Claude 5 refusal in this suite came from bare code prompts over the raw API; the Maia agent evals run on Fable without a single refusal.

Recommendation

For autonomous code agents on the raw API, Gemini 3.8 Flash, Kimi K3 and Grok 4.5 are the frictionless choices, with Gemini now leading on accuracy and cost. Fable 5.1 is viable where a supervising loop can detect a refusal and re-route (its accuracy is the best in the set), and its refusal rate should be re-measured on each model release since it moved from 30 to 8 between Fable 5 and 5.1. Keep the suite in the repository and re-run calibrate before every comparison.
